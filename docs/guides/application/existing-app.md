# Add Runic to an existing app

Use this path when you already have a .NET console or desktop project and a
frontend, and want them to talk through typed Windows and Views. To start from
nothing, [create a project](getting-started/README.md) instead; the steps below
reproduce what the template sets up. Replace `<VERSION>` with the current
release from the [package catalog](https://docs.runic-artifex.eu/packages/) and
keep Application SDK packages on that version. Runic Translations and Runic
Command Line have independent release versions.

For a package-only GTK 4 consumer and its scoped/native shutdown ownership, see
[Build a desktop app from published packages](package-consumer.md).

For an existing WPF shell, follow [incremental WPF migration](migrations/wpf-incremental.md)
to add native navigation or embed an individual web View.

## 1. Add the packages

Choose one host adapter. Runic Desktop, the default, opens native windows with
the embedded WebView and adds platform services. CS-WebUI opens a browser
window and is supported on a best-effort basis
(see [choosing a host and MVVM library](choosing.md)):

```sh docs-test=commands
dotnet add package Runic.Application.Views.Desktop --version <VERSION>
# or, for a browser window:
dotnet add package Runic.Application.Views.CsWebUi --version <VERSION>
```

Add the ReactiveUI adapter, which brings ReactiveUI 26, and the dependency
injection container at the version the template uses:

```sh docs-test=commands
dotnet add package Runic.Application.Views.ReactiveUI --version <VERSION>
dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.12
```

For CommunityToolkit.Mvvm ViewModels, add `CommunityToolkit.Mvvm` instead of
`Runic.Application.Views.ReactiveUI`:

```sh docs-test=commands
dotnet add package CommunityToolkit.Mvvm --version 8.4.2
```

## 2. Opt the project in

The host adapter brings the build targets. They expect the frontend in a
`Frontend` folder next to the project file; set
`RunicApplicationFrontendDirectory` if yours lives elsewhere. Opt in to
`dotnet runic dev` and `dotnet runic doctor` in the project file:

```xml docs-test=template:RunicWindowApp.csproj
<RunicApplicationFrontendWindowProject>true</RunicApplicationFrontendWindowProject>
```

Install the project-local `dotnet runic` tool:

```sh docs-test=commands
dotnet new tool-manifest
dotnet tool install --local dotnet-runic --version <VERSION>
```

## 3. Declare a Window and its Views

Keep your ViewModels as they are; they need `INotifyPropertyChanged` and at
least one property or command. Declare the Window over the root ViewModel and a
View for each ViewModel the Window presents:

```csharp docs-test=template:Views.cs
public sealed partial class WorkspaceWindow : RunicWindow<WorkspaceViewModel>;

public sealed partial class WelcomeView : ReactiveRunicView<WelcomeViewModel>;
public sealed partial class CounterView : ReactiveRunicView<CounterViewModel>;
```

With CommunityToolkit.Mvvm, the Views are `RunicView<TViewModel>`. A Window
with a single ViewModel needs no Views.

## 4. Register and open the Window

Register each ViewModel with the lifetime your application needs; the Window's
root ViewModel must be scoped. `AddRunicViews()` is generated for your project,
and `AddRunicPlatformServices()` gives ViewModels the Window's file dialogs
and clipboard:

```csharp docs-test=template:WorkspaceServices.cs
public static IServiceCollection AddWorkspace(this IServiceCollection services)
{
    services.AddRunicReactiveModelContext();
    services.AddScoped<WorkspaceViewModel>();
    services.AddScoped<WelcomeViewModel>();
    services.AddScoped<CounterViewModel>();
    // Generated by the build: the Window and View Bridges and the View locator.
    services.AddRunicViews();
    // ...
    services.AddRunicPlatformServices();
    return services;
}
```

With ReactiveUI, `AddRunicReactiveModelContext()` runs the commands'
notifications on the Window's model context; leave it out with
CommunityToolkit.Mvvm. Then run the application on the host, and open the
Window in its body. `RunicDesktopHost.Run` starts the event loop the platform
needs, so call it before any `await`:

```csharp docs-test=template:Program.cs
await using var provider = new ServiceCollection().AddWorkspace().BuildServiceProvider(new ServiceProviderOptions
{
    ValidateScopes = true,
    ValidateOnBuild = true
});
...
return RunicDesktopHost.Run(provider, options, RunAsync);
...
static async Task<int> RunAsync(IRunicWindowHost host)
{
    await using var window = await host.OpenWindowAsync<WorkspaceWindow>(new RunicWindowOptions { Width = 1000, Height = 700 });
    await window.WaitForCloseAsync();
    return 0;
}
```

The Window serves the built frontend from the `www` folder next to the
executable. With CS-WebUI, call `RunicCsWebUiHost.Run(provider, RunAsync)`
instead; the body is the same. The [tutorial](tutorial/README.md#4-register-and-open-the-window)
walks through the generated `Program.cs`.

## 5. Connect the frontend

From the frontend folder, install the shared runtime and the binding for your
framework:

```sh docs-test=commands
npm install --save-exact @runic-artifex/views@<VERSION>
npm install --save-exact @runic-artifex/react@<VERSION>
```

Use `@runic-artifex/vue`, `@runic-artifex/svelte` or `@runic-artifex/angular`
for those frameworks, or only `@runic-artifex/views` for plain TypeScript. Vite
projects can add `@runic-artifex/vite-plugin-runic` as a development
dependency for Runic diagnostics; with Runic Desktop, `runic({ desktop: true })`
also loads the Desktop bootstrap.

The page loads the host's scripts before your module. With Runic Desktop:

<!-- prettier-ignore -->
```html docs-test=template:frontends/react/index.html
<script src="webui.js"></script>
<script src="runic-desktop-views.js"></script>
```

With CS-WebUI, load `runic-cswebui.js` instead of `runic-desktop-views.js`.

`dotnet build` now writes the typed clients to `Frontend/src/generated`, builds
the frontend with its `build` script and copies `Frontend/dist` to `www` next
to the executable. Add `Frontend/src/generated` to `.gitignore`. Build the
frontend with relative asset URLs (Vite's `base: "./"`) so the `www` folder can
move. The [tutorial](tutorial/README.md#5-render-the-views) shows how the
generated clients are used from components.

## 6. Run it

```sh docs-test=commands
dotnet tool restore
dotnet runic dev
```

`dotnet runic doctor` reports a missing opt-in, package or frontend lock file.
